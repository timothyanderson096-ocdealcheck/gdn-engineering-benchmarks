# BatteryBox mandatory candidate gates

This helper validates the two-file module-label candidate at `timothyanderson096-ocdealcheck/byd_battery_box@d812e7bd22cc2aefa18614b31aba48276e496565`. It restores `TimWeyand/byd_battery_box` at `2cc576278e05b7bb1778f1a50246b8072dc77883`, verifies the immutable patch's SHA256, applies the complete patch, and checks both resulting Git blobs. Before HACS it verifies the public fork's identity, exact commit parent and complete Git tree against that local base plus patch. It never runs the integration's hardcoded-device `client_test.py`.

The Ubuntu 24.04 workflow uses Python 3.14.8, Home Assistant 2026.10.2, pymodbus 3.13.1, pytest 9.2.0, pytest-asyncio 1.4.0 and Ruff 0.17.3. It requires exactly seven passing data-only regressions, runs the project's integration lint plus the added test, and compiles all integration Python files and the new test with Python 3.12.14. Tests guard socket connections and use synthetic balancing data; they do not exercise a configured Home Assistant lifecycle or physical battery.

The Docker phases use the normal entrypoints of immutable Linux amd64 images: hassfest `sha256:e2576d17e5af7a99c7b91ab852467914b330d63d4c092df27105e5a0c6540bfc` and HACS `sha256:35241cb9a8ce6a83f3fbe893880283419c59bea26e71d4c99e279856518bde25`. Hassfest reads the complete patched source tree; HACS fetches the actual public fork at the exact candidate SHA. HACS receives the actual repository, explicit integration category and exact ref, with all ten applicable integration validators enabled. It uses the workflow's ephemeral read-only GitHub token through environment forwarding, never a token literal in command arguments. `INPUT_COMMENT=false` is supplied; the pinned HACS entrypoint contains no comment-posting code. No release workflow is inherited or invoked.

Every subprocess records its actual exit status. Timeouts and checks that never ran remain distinguishable from passing checks. Only when every recorded required gate and native regression passes does the report say `MANDATORY_GATES_PASSED`. Informational mypy and Bandit checks remain outside this job; a mandatory-gate pass does not claim physical battery validation or configured Home Assistant lifecycle coverage. Only explicitly listed validation reports and command logs are uploaded.

The workflow runs when its exact helper/workflow paths change on `main`, or through manual workflow dispatch. Repository access is read-only; checkout credentials are not persisted. The report distinguishes the GDN workflow repository from the BatteryBox candidate repository. This helper creates no commits, pull requests, tags, releases, credentials or hardware connections.
