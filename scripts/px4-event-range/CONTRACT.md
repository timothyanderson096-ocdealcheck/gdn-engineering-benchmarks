# Native wire fixture contract

The separate baseline capability job verifies unchanged source. This follow-up tests a proposed one-hunk candidate with real native protocol traffic and records its exact boundaries; it does not submit the source to PX4 or attest personal review or DCO certification.

The generated Python dialect must come from the exact tested checkout's pinned MAVLink submodule and its recursive pymavlink generator, using `development.xml` (as selected by the SITL board), with source/XML/generator/generated hashes recorded. No fabricated historic pymavlink package-version attribution is allowed. The registry package resolved by official setup is recorded by pip freeze, while the actual client generator source is explicitly selected with PYTHONPATH.

`wire_probe.py` boots normal SIH (`sihsim_quadx`, airframe 10040) from an actual full `px4_sitl_default` binary in a new rootfs. It binds only 127.0.0.1:14540; normal upstream offboard MAVLink originates at 127.0.0.1:14580, system/component 1/1. Client 245/190 sends GCS heartbeats, one disarmed prearm-check command, read-only parameter requests, and REQUEST_EVENT. It sends no arm, mode, mission, actuator or flight command.

Actual startup heartbeat and accepted prearm-check ACK must exist; a genuine EVENT is discovered and its full decoded payload retained as the cached-event oracle. Cases are cached single, unavailable single, a real oldest-available-hint to cached-EVENT follow-up, an ordinary three-sequence range, a short wrapped range 65534 → 1, near-full 0 → 65534 (65535), full 0 → 65535 (65536), cached-after-full, rotated full cached → cached-1 (65536), and another cached control.

Every range requires exactly one real EVENT or RESPONSE_EVENT_ERROR for each inclusive uint16 sequence and no extras/duplicates, in the exact requested cyclic order. Cached EVENT contents must match the discovered original. Error reason must be UNAVAILABLE and target client 245/190; EVENT destination must be broadcast 0/0. The unavailable-single case explicitly requires one ERROR, not an arbitrary message. Ordinary/short-wrap cases exercise counts independent of the candidate. The baseline's full-cycle failure remains a regression result, not a successful native gate; an orchestrator must require the exact six failing full-cycle count/order/cached-content assertions and no control/setup failure. Candidate requires every assertion passing.

Collection uses an ordinary UDP socket without capabilities or sysctl changes, requests a large receive buffer and records the actual granted size plus Linux SO_RXQ_OVFL counters. A pinned C++ recorder reads that same Python-bound socket through an inherited file descriptor and writes raw datagrams without MAVLink decoding. The Python sender keeps the same descriptor, endpoints and initial buffer request. The recorder inherits the wire probe's process group so the outer watchdog bounds both. Its source, compiler command and compiled binary identity are recorded; final recorder status, complete journal framing and packet-count agreement are required. See [capture/README.md](capture/README.md). Decoding follows each fixed finite capture window. Full/near-full windows are 20 seconds, small controls 1.5 seconds. These are observation deadlines, not response caps. Kernel receive loss, framing/CRC faults, truncation, unexpected endpoints, an armed heartbeat, or unstable event-buffer sequence is a failed control/infrastructure boundary. Never turn partial delivery into a complete 65536-response claim.

Unsolicited EVENTs cannot be transaction-tagged by MAVLink. Thus periodic CURRENT_EVENT_SEQUENCE must stay equal to the pre-test latest sequence, and bulk cases must observe it. Otherwise changing event production makes exact counts ambiguous and the fixture fails that control. This is deliberately conservative; do not silently ignore extra events or waive the stability assertion to get green.

A read-only MAV_SYS_ID request is scheduled after an intended 10 ms wait following each REQUEST_EVENT. The actual transmit offset is recorded as `actual_read_only_request_offset_seconds`; no exact scheduler timing is assumed. Response matching requires its timestamp to follow the actual parameter-request transmit timestamp. Its first real response measures receiver latency during synchronous response work; continuing heartbeats and their maximum gap are recorded. Recorder timestamps are dequeue observations, not kernel arrival times. Full/near-full raw timings permit comparison. Finite completion is tested, but no universal latency budget or maintainer acceptance is invented.

Artifacts retain per-response decoded JSONL, transmit packet bytes, full native log, exact process exit/cleanup and a raw UDP journal. `wire.udp` begins with ASCII `PX4UDP1\n`; records have little-endian header `<Q4sHHI` (monotonic nanoseconds, source IPv4, source port, payload length, cumulative kernel drops) followed by exact UDP payload bytes. The sender stops before the recorder is drained and closed; any recorder error, truncation, loss or forced stop fails. The fixture handles SIGTERM through its cleanup path. An actual PID/process-group/start-time journal lets the outer timeout watchdog clean that same PX4 process safely if the fixture must be killed.

Normal shutdown is attempted even after an earlier control failure, which remains failed. `shutdown-proof.json` records the exact owned native process alive before the real CLI command, the pre-request daemon-log offset, actual CLI status/output and bounded natural native exit. Both accepted paths require natural exit 0, a fresh terminal `Exiting NOW.` marker, no timeout or signals and no earlier unexpected harness/control failure. CLI 0 is `ACK_OBSERVED`. Only CLI 255 with completely empty combined output may be `NOT_OBSERVED_SOURCE_PERMITTED_SHUTDOWN`; no other nonzero status is accepted. In the pinned POSIX source, shutdown queues an HPWORK worker that can exit before the daemon writes the RPC trailer; the client's missing-trailer EOF path returns -1/255. This observation does not prove the exact thread schedule, an RPC ACK for 255 or that every shutdown hook/resource drained. Signal cleanup is used only for a still-live process and keeps validation failed.

That observation follows the pinned [shutdown command](https://github.com/PX4/PX4-Autopilot/blob/789389fd46fcfb8473544d2fb3eeabd85893294c/src/systemcmds/shutdown/shutdown.cpp#L41), asynchronous [request and worker](https://github.com/PX4/PX4-Autopilot/blob/789389fd46fcfb8473544d2fb3eeabd85893294c/platforms/common/shutdown.cpp#L291), daemon [return-trailer write](https://github.com/PX4/PX4-Autopilot/blob/789389fd46fcfb8473544d2fb3eeabd85893294c/platforms/posix/src/px4/common/px4_daemon/server.cpp#L292) and client [missing-trailer EOF handling](https://github.com/PX4/PX4-Autopilot/blob/789389fd46fcfb8473544d2fb3eeabd85893294c/platforms/posix/src/px4/common/px4_daemon/client.cpp#L147). The marker must be a fresh standalone line; later exit logging does not invalidate it.
